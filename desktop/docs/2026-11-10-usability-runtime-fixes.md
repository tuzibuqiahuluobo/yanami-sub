# 0.3.0 后续可用性与 Python 环境修复

## Python 环境根因

FineSub 0.7.0 的 Windows 锁同时包含 `onnx==1.23.2` 和
`onnx-weekly==1.23.0.dev20260805`。核对按锁中 SHA-256 验证的官方 wheel 后，
发现两者恰好有 **114 个同路径文件的内容不同**，包括 `onnx/__init__.py` 和
`onnx/_mapping.py`，与用户截图吻合。两个包安装到同一个 `onnx/` 命名空间；
要求每个文件同时匹配两份不同的 RECORD，会造成无法通过的校验。

不能简单删除 weekly：`audio-separator` 和 `onnx2torch-py313` 都声明依赖它。
也不应关闭校验或直接归因于杀毒软件。

桌面层保留上游锁和原有校验，只在以下条件同时成立时处理冲突：

- 两个发行包均在当前锁中，安装版本正确，无重复元数据。
- 其中一整套发行包的已记录文件完整且哈希正确。
- 另一套的哈希差异仅涉及上述完整发行包同样拥有的 `onnx/` 文件。

不接受逐文件混合版本，不忽略缺失、非共享文件损坏或错误版本。
安装暂存区、完整性检查与已完成暂存区复用都使用同一规则。
真实损坏仍会清理对应包缓存、重装一次，失败则拒绝替换旧运行环境。
错误提示列出可能原因，不再断言安全软件隔离。

## 设置和任务日志

- 路由、各 Agent 配置和 CLI 就绪检测合并到一个默认收起的设置区。
  每个 Agent 只显示一行，包含就绪状态与配置入口；CLI 就绪不等于账号可用。
- 普通 API、检索服务、云端转写与自定义凭据合并到另一个折叠区。
  从任务引导前往设置时自动展开对应区域，云端凭据缺失不再跳到路由区。
- 任务与批次日志统一每页 10 条，支持名称筛选、页数/总数、上一页/下一页。
  筛选从第一页开始；总数减少时校正页码，较旧响应不覆盖新页面。
- 新建任务和批处理使用同一款 Agent 配置快捷按钮，替换未样式化的灰色长条。

## 知识库分析与优化

知识库已有条目、字幕反馈、提案审阅、维护/恢复、社区共享等基础能力；
主要可用性障碍是默认暴露机器模板、术语过多，以及模型调用和写入边界不清。

- 默认显示可读正文，隐藏模板注释但不修改原文。高级编辑保留完整源文本。
- 使用“从字幕学习”“检查与恢复”“社区共享”等直白名称，并说明每页的操作顺序。
- 双语字幕导入移到学习页前面，明确不需要原任务；已有任务的精修导入保留。
- 区分“查看计划”“生成建议”“生成并写入”；维护工具的预览与执行为独立运行，
  不将其宣传成同一份提案。精修提案的应用则使用已审阅提案，不重复调用模型。
- 切换条目前提示未保存的编辑；正文按 React 文本渲染，不执行导入的 HTML。
- 双语导入随核心使用 CodeBuddy/旧 WorkBuddy 选项。失效的已保存 Agent 提示重新选择，
  不静默改用可能收费的 CodeBuddy。

本轮不改变知识推理算法，不保证提取内容必然正确；仍需审阅提案。

## 拖放

原生 WebView 之前只转发第一个完整路径，且只有新建任务页订阅。
现在保留全部完整路径，批处理页面可一次加入多个文件并去重；
只在可接收的当前页面处理事件。保留文件选择器作为键盘替代入口。

## 验证范围

使用隔离目录和已校验的真实 ONNX wheel 复现 114 项差异，并验证修复后
接受完整安装、拒绝篡改。执行相关后端与前端回归、类型/静态构建检查，
浏览器核对深浅色、折叠跳转、日志分页与多文件原生事件处理。
结果：相关后端 140 项通过、1 项跳过；前端 145 项通过；类型检查、生产构建与
WebView 静态导出检查通过。日志模拟 23 条记录验证为 10/10/3，筛选和页码校正通过。
没有改动用户的已安装运行环境、知识库或凭据；未调用付费模型。
未运行完整 GPU 任务，也未用新安装包进行资源管理器拖放实机复测。
用户随后授权打包、推送与发布。补丁版本为正式版 `0.3.0.post1` 和
预览版 `0.3.1-rc.1.post1`（RC1.1）；构建使用 GitHub Actions，更新签名在本机完成。
