# 应用版本完整性与恢复（RC7.1）

## 已有能力和缺口

RC7 的在线清单由 Ed25519 签名，应用 ZIP 经大小与 SHA-256 验证后，整体解压到 staging，再原子切换版本指针；并不存在逐文件增量复制。启动可检查 `REQUIRED_APP_FILES` 并回退旧版本。然而该列表很短，缺少 `agent_health_check.py` 等被导入模块：残缺目录可能被误判完整。`app-manifest.json` 目前仅含版本和平台。

## 方案

1. 打包时为版本目录生成文件清单及 SHA-256（不包含清单自身），由已签名的 ZIP 资产整体保护。清单记录路径、大小、摘要；路径限版本目录内的普通文件。保留 `app-manifest.json` 的现有版本/平台字段以兼容旧安装器。
2. 安装 staging、复用已有同版本目录、启动确认健康时都共用一个验证函数：先核对入口与必要模块，再核对清单文件的存在、大小和摘要。不可把“只要七个文件存在”当作健康。
3. 启动时校验当前版本；不完整则扫描已安装的其他版本，从新到旧选最近的完整版本，原子更新 `current.json`，保留坏版本以便诊断。全都不可用时显示“安装损坏，请重新安装”，不能泄出 PyInstaller traceback。旧版本没有文件清单时以扩充后的必需文件列表兼容验证，不宣称已做逐文件哈希验证。
4. 校验范围只限不可变的应用版本目录；用户数据、模型、缓存和 Python runtime 不属于应用包校验。正常启动尽量避免重复读取大模型和用户目录。
5. **RC7.1 改动冻结启动器代码**，因此 RC7→RC7.1 以及更旧版本必须走完整更新包；签名在线清单仍必须发布。不得把旧 RC7 宣称为安全的 app-only 更新来源。

## 验收

- 删除或改动任一受保护模块、前端静态文件时，当前版本不再被选中；前一完整版本自动接管。
- 没有可用版本时出现双语安装损坏提示；旧版无清单的兼容行为有独立测试。
- 已验证且完整的同版本目录可复用；损坏的同版本目录必须重新从已校验 ZIP 提取。
- 测试更新清单签名、资产摘要、staging、指针切换和启动恢复；不移动旧 tag，也不改用户数据。
