# RC7.7 发布范围与验证边界

版本：`0.1.2-rc.7.post7`。共用可靠性修复同时进入正式版 `0.1.1.post2`，新增反馈、音效与日志浏览先在预览版提供。

## 可靠性

- Numba 的标准 JIT 缓存不再被误判为篡改；必须位于 `__pycache__`，且对应受哈希保护的源码。后续 worker 的缓存迁出版本树，进入可迁移的数据根 `cache/numba`。缺失/修改源码、异常链接与任意额外文件仍拒绝。
- GUI 使用 Windows 命名互斥量，同用户数据域只允许一个实例；再次启动唤醒现有窗口。启动日志早于完整性检查，失败可记录具体路径。
- WorkBuddy 明确认证失效不再反复按瞬时网络错误重试；由用户在官方客户端登录，应用不复制 token。CLI 就绪探测不是登录或模型权限证明。
- 手动路由、新建与批处理共用能力适配，纯文本 Agent 不会被当成音视频模型；保留用户明确绑定的候选链。
- GitHub Actions 仅手动构建和下载产物，不自动发布。当前发布在本机用既有可信 Ed25519 私钥签名，未上传私钥。

## RC7.7 新功能

- 设置底部提供任务目录与日志列表，包含未入历史索引的任务及共享批次日志；不会声称每项都有独立批次日志。
- 完成页和磁盘日志显示真实输出/日志位置。全局完成通知与声音在切换页面后仍工作，不为失败、跳过或旧历史记录播放成功音效。
- 外观设置增加默认完成音效（用户提供并允许公开分发），默认启用、音量 50%，可分别关闭任务/批次/下载事件。播放失败不影响业务。
- GitHub Issues 独立窗口不挂载本地桌面桥接，支持转浏览器继续；应用只预填摘要，用户在 GitHub 登录、选择附件并最终提交。
- 诊断 ZIP 仅在显式点击后本机生成：用户选择的任务/共享批次日志、近期应用/安装运行日志与已有更新错误。不会导出媒体、字幕、配置、Agent 会话或凭据文件；逐份截取最新 512 KiB、总计至多 30 文件/16 MiB，并脱敏配置密钥、常见 token、代理密码和个人路径。
- 自动脱敏不能保证发现所有自由文本隐私。UI 要求用户检查后才上传；不收集 Windows Event Log 或自动上传附件。

## 发布和更新

两个频道均要求完整更新包，最低启动器版本等于目标版本，以更新冻结启动器；应用增量包不能修旧启动器。无法启动者请退出后同路径覆盖安装，不必先卸载，不清空模型、设置或任务。

正式版默认只接收正式更新；开启预览更新后可接收更高版本 RC。RC 用户保持预览频道。版本序保持 `0.1.1.post2 < 0.1.2-rc.7.post7`。

已通过的自动化与构建结果见 Actions 和发布记录；这些不替代用户 RTX 5070、驱动、供应商账号登录及完整付费模型任务的实际验证。
