# 内置视频封装与字幕压制评估（2026-11-13）

本轮仅分析，不实现或宣称已有压制功能。可行性高，但应在字幕任务之外作为独立、可取消的交付工具，不默认自动运行。

## 先区分两种结果

| 方式 | 用户得到什么 | 成本与限制 |
| --- | --- | --- |
| 软字幕封装，优先候选 | 将视频、音频和可切换字幕装进新 MKV；播放器决定显示样式 | 合适的编码/容器可以 stream copy，不重编码画面；播放器和容器对字幕的支持不同 |
| 烧录字幕，后续可选 | 字幕永久成为画面的一部分 | 需要解码、渲染和重新编码视频；耗时并可能有损，不能再关闭字幕 |

这些能力可复用现有 FFmpeg，无需增加另一套媒体后端。FFmpeg 文档明确区分 streamcopy 和 filtering/transcoding；烧录的 subtitles 滤镜需要带 libass 的构建。具体二进制能力必须在运行时查询，不能由文件名推断。[官方命令说明](https://ffmpeg.org/ffmpeg.html#Streamcopy)、[subtitles 滤镜](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1)。

## 建议的最小产品范围

首期只接受本地视频和已有 SRT/ASS，预览轨道、语言与时长；默认“新建 MKV + 软字幕”，保留原视频。用户单独开启“烧录字幕”时才选择字体、字号、位置、质量和硬件编码，先输出短片段预览。独立进度、取消与日志；失败保留原文件，不把编码失败当成字幕识别失败。暂不承诺跨进程断点续编码，重编码续接涉及 GOP/时间基与音画同步。

## 风险和必须的防护

- 画质与 HDR：默认不缩放、不改帧率；HDR、色彩空间、10-bit、VFR、多音轨等不能套一个通用参数。首期可明确只覆盖 SDR 常见格式，其他素材提示限制，不静默转色。
- 性能：CPU 编码可能很慢；NVENC/QSV/AMF 是否可用取决于实际 FFmpeg、驱动和硬件。先探测并小样本试跑，失败不能无限重试；不要与 ASR 同时抢 GPU，用户仍可选择 CPU。
- 空间：检查输出盘和实际临时盘，给出估算与余量。使用同目录临时输出，校验完成后原子更名；禁止覆盖输入，默认新文件名。同名文件必须显式处理。
- 字幕：检查 UTF-8/BOM、中文/日文字体与缺字、ASS 字体/定位、字幕时长超过视频、负时间戳等。SRT 到 mov_text 可能丢样式，不能声称所有容器无损兼容。
- 安全：参数列表启动 FFmpeg，不拼 shell；只允许本地常规文件，限制协议。字幕路径需处理 Windows 盘符与滤镜转义；字体附件不能未经审核就装到系统。取消时终止本次受管子进程，不杀其他应用的 FFmpeg。
- 分发与许可：须核对所用 FFmpeg 构建的许可、配置、源代码对应关系和第三方字体授权，不能简单理解成“开源所以任意分发”。是否涉及 GPL 组件、nonfree 选项及编解码专利需按具体构建和分发地区另行审核。[FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)。

## 决策

建议列入下一独立功能迭代，优先软字幕封装，再决定是否加入烧录；本轮不增加二进制或依赖、不改字幕主流程。验收至少覆盖中/英/日字幕、中文和特殊字符路径、长视频、大文件、磁盘不足、取消、GPU 不可用、原文件保护和音画同步。以上是工程评估，不替代具体发行物的许可审查。
