# DSH 与本地 Agent 发现（RC7.1）

## 目标与边界

用户把 `deepseek-harness` 安装在 `G:\deepseek-harness` 一类非标准位置时，RC7 的安全自动扫描只看用户目录、PATH 和全局 npm 安装，因而可能找不到它。恢复“扫描每个盘符根目录”会重新引入不可信 `bin.js` 自动执行及断开映射盘卡顿，不能采用。

## 方案

1. 保留 PATH、npm、用户目录的窄范围自动发现。对目录访问、Windows 重解析点和 `WinError 448` 单独容错：一个坏候选不能使启动或整次检测失败。
2. 在设置的“本地 Agent 就绪检测”附近提供明确的 DSH 路径输入和保存/清除操作。可填 `deepseek-harness` 源码根、受支持的 `bin.js`，或本机 `dsh.exe`。保存时验证精确路径和文件类型；源码脚本须位于预期的 `apps/cli/lib/bin.js`，并使用已发现的本机 `node.exe`。应用不可自行猜测任意盘符位置。
3. 所选路径存到桌面偏好设置，刷新后端当前命令映射和之后任务的 worker 环境；不会把用户路径写入公开任务报告、Release 或通用模型配置。发现阶段不执行候选。用户点击“就绪检测”时才运行轻量探针，真正账号/额度能否用仍由任务调用判定。
4. 显示“已发现”“可启动”“已完成真实任务”三种不同语义；`--version` 返回非零不能被标记为可用。失败时保留本次错误，并按现有路由顺序继续下一个 Agent。
5. 仅当用户明确选择该路径时信任其内容；提示源码 CLI 会执行本机代码。不得跟随自动枚举出的可移动盘、网络映射盘或任意同名目录。

## 验收

- 指定 `G:\deepseek-harness` 后能识别真实 CLI；重启与重新扫描后仍存在；清除后回归自动发现。
- 坏路径、缺 Node、无权限、失效 junction、`WinError 448` 和不支持的文件均产生可解释结果，不阻断应用启动。
- 测试构造隔离环境，不读取开发机真实注册表 PATH；不使用虚假的 `setx YANAMI_SUB_DSH_PATHS` 临时方案（RC7 并未实现该环境变量）。
