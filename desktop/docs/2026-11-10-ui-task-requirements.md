## 具体范围和验收标准

### UI-01：说话人设置遮挡

- 现象：高级设置中，“说话人模型”下拉框遮挡“人数上限”输入框。涉及 `desktop/frontend/components/SpeakerSettings.tsx`。
- 两个控件及标签在窗口缩放、较窄窗口、长选项和中英文界面下均不重叠、不截断关键内容；空间不足时自然换行。验证新建任务和复用此控件的批处理页面，以及键盘操作和浅色/深色主题。
- 用户的后续工作偏好：以后在已授权的开发任务范围内发现类似遮挡，应及时修复并验证，无需再逐个询问。**本次明确只记录，不立即修复。**

### UI-02：阶段换行的垂直间距

- 用户反馈：阶段增多时出现多行，行与行过近。现有 `desktop/frontend/components/ProcessingView.tsx` 使用阶段列表，`desktop/frontend/app/styles/task-run.css` 的 `.stage-list` 为自适应网格，当前未显式设置行间距；这是待验证的相关线索，不是已经复现的根因。
- 处理方向：设置一致行距，同时检查连接线、状态文字、复用和跳过标记在多行时的位置；窗口宽度变化不应造成重叠或错误连接。
- 附图一与图二是同一张说话人设置截图，因此此项依据文字记录，后续实现时需实际复现或补充对应截图。

### UI-03：移除多余的勾选 UI

- 用户要求去掉额外的“知识库自动更新”打勾 UI；仅移除对应冗余展示，不应因此关闭知识库更新、删除用户配置或改变实际任务行为。
- 图三可见大勾位于“使用预设默认参数”上方；代码中该处存在控制 `llm_preset_defaults` 的复选框。截图不能证明它就是用户提及的知识库自动更新标记。以后实施前应先确认是异常放大的复选框、多余阶段标记，还是其他独立控件；不要直接删除预设参数功能。

### UX-04：任务预设更易理解

- 对默认、AGY 混合、AGY 独占、AGY 快速、API 快速等提供易懂的名称和说明，至少说明模型来源、适用场景、速度/质量倾向与可能的额外条件。
- 文案以届时实际上游路由和配置为准；不要仅凭名称承诺免费、支持音视频、必然回退或一定更快。保留原预设 ID 及兼容性。
- 中英文均提供清晰说明；不影响手动选择和现有配置。

### OPT-05：保存上一次选择

- 在设置中提供“记住上次使用的设置”开关，覆盖新建任务、批处理、知识库相关设置；新建下一任务及重启后按开关恢复，允许用户再次更改。
- 现状：`desktop/frontend/app/page.tsx` 已调用 `rememberTaskOptions`；`desktop/frontend/lib/preferences.ts` 与 `state.ts` 已有 `task_defaults`。实施前逐项盘点覆盖范围和生效时机，补齐批处理与知识库，不与既有默认值机制冲突。
- 建议明确开关关闭后的行为、恢复默认入口与跨页面优先级；区分常用选项和一次性的文件路径、任务队列、私密内容，避免把 API 密钥或日志内容当普通偏好保存。自动清理、可能产生费用等敏感选择必须清晰告知，避免静默产生意外后果。具体默认开关状态和特殊字段范围在实施设计时确定。
- 验收覆盖三处页面、重启/新任务、关闭开关、旧配置升级、缺失字段和单次覆盖，不得泄露密钥或覆盖已有数据。

### ERR-06：模型调用失败提示

- 纠错翻译失败时，在任务界面及日志展示清晰原因与可操作的建议；可能情况包括模型不可用或无权限、API 认证失败、额度/速率限制、网络与代理故障、超时、Agent 未登录等。
- 有明确错误码时呈现对应原因；不能确定时标为“可能原因”，保留可脱敏的原始错误，不把所有失败都归咎于额度或无效模型。提供对应的设置入口及重试建议。
- 如发生回退、跳过或部分完成，要准确说明实际结果，不能显示为完整成功；不改变既有结果、断点与清理策略而未评估。

### LOG-07：记录实际模型

- 对每个实际使用模型的阶段记录来源、模型/Agent 标识及阶段；发生切换或失败重试时体现真实过程，避免把候选顺序误写成实际成功使用。对未知或不可观测的模型如实标注未知。
- 若全程确实只用了同一模型，汇总只标一次，并说明覆盖范围；若不同阶段或重试使用不同模型，则按阶段或切换记录，避免同一信息大量刷屏。
- 现有 `desktop/backend/worker/main.py` 和 `batch_main.py` 已输出模型来源与尝试顺序，不能据此断言最终实际使用的模型；须兼容已有底层日志并避免重复。
- 日志不得包含 API 密钥、认证信息、敏感代理地址或不必要的任务内容；覆盖单任务和批处理、失败及回退场景。

### UX-08：设置项文案

- 将“路由预设、执行策略、服务档位、推理强度、单次超时、最大并发、允许读取用户配置”等翻译为易懂的名称、用途、影响和适用条件；高级术语可保留为次要说明。
- 特别说明并发与额度、速度的关系；读取用户配置的隐私/隔离影响；超时不代表保证成功。中文、英文的文案语义保持一致。

### UX-09：Agent 独立配置弹窗

- 外部列表以 Agent 名称及“配置”入口为主，状态信息可保留以帮助判断可用性；每个 Agent 的弹窗放置其专属配置与该 Agent 的安装路径/选择入口。
- Agent、模型和 API 路由并非同一概念：真正跨 Agent 的预设、执行策略或通用并发等设置应保留在合适的公共区域，不要为了外层精简而隐藏或复制成互相冲突的设置。
- 保持旧路径、路由配置、凭证及默认行为兼容；明确保存/取消与未保存提示，弹窗支持键盘、焦点和窄窗口，保留可信路径校验。不同 Agent 只显示其真实支持的选项，避免暗示 CLI 检测等于登录或额度有效。

## 建议实施顺序

1. 修复 UI-01、UI-02，并改善 ERR-06 的错误分类及提示。
2. 盘点 OPT-05 的既有行为并补齐，随后完善 LOG-07。
3. 确认 UI-03 指向后处理，再完成 UX-04、UX-08 的说明和 UX-09 的设置结构调整。
