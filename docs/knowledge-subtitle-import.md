# 人工精修字幕与知识库

## 两种入口

- **独立双语字幕**：知识库 → 任务反馈 → 导入人工精修双语字幕。没有原任务也可以使用；选择原文 SRT 与人工润色译文 SRT。条数、每条起止时间必须完全一致，字幕编号不要求相同。
- **已有任务回灌**：知识库 → 任务反馈 → 选择已完成任务 → 精修字幕回灌。需要保留原任务的 stable JSON、annotated CSV、最终 SRT 等材料；缺失材料会明确报错，不伪造 ASR 记录。

## 双语导入步骤

1. 在“条目”中创建对应的通用知识/主播条目；若要学习字幕组的表达习惯，另建“字幕风格”条目。
2. 选择两份 SRT。默认读取 UTF-8 或带 BOM 的 UTF-16；旧中文/日文文件可手动选择 GB18030 / CP932，不猜测歧义编码。
3. 点击“检查时间轴”：不调用模型、不写知识库；核对条数和前十条对照。
4. 选择目标条目，以及可选的风格条目。独立选择自动/API/Agent/手动模型路由，也可继承已有任务的来源、指定 Agent、模型与难度。
5. 点击“生成提案”：会调用模型，但不写入知识库。逐条审阅提案，尤其是译名、别名和风格，不应把偶发剧情或整份字幕当作长期知识。
6. 点击“应用已审阅提案”：提交保存的同一份提案，不再调用模型。知识库期间发生变化时需要重新生成；冲突、部分提交、无变化会分别报告，不统称成功。

双语文本不是 ASR 误听证据，也不是模型训练。导入提案不得创建/停用/重命名其他条目；知识条目与可选风格条目分别生成有作用域的提案。模型输出的 ASR 误听项目会被拒绝。

## 已有任务的继承

API/Agent 来源、指定 Agent、手动路由和处理难度来自保存的任务请求。风格名称按 FineSub 的选择器解析；只有原任务允许 `style_mode=update` 时，回灌才获得风格写入权限，`read`/`none` 不会悄悄变成可写。

## 安全与结果

提案存放在用户数据根下的 `knowledge-proposals`，与真实知识库分开；只保存提案、来源摘要、文件哈希、条目绑定与读取版本，不保存 API 密钥。应用按编号加载原提案，并通过 FineSub 原有的写锁、校验、SQLite 版本事务与 CAS；重复点击不会重复提交。提案提交失败时保留诊断报告，处理过的提案重试返回原结果。

报告“已生成”不代表知识库更新；“已提交”表示实际产生版本事务；“部分提交”“未提交”“无变化”须查看报告。多个块并不是一笔跨块全有或全无的事务。

## 升级桥接

0.1.1.post4 和 RC7.9 均先安装正式版 0.1.2。0.1.2 的预览更新需主动开启，之后可升级 0.1.3 RC1.0（版本标签 `v0.1.3-rc.1`）。新预览使用 v2 清单资产名，旧 RC7 更新器不会直接发现它；签名格式和信任公钥不变。两次升级使用完整更新包，同步冻结的启动器/桥接接口。
