# Yanami Sub 0.1.0 RC6.1

RC6.1 是针对更新可靠性、API / Agent 可用性与密钥引导的修复版，内部版本串为
`0.1.0-rc.6.post1`。字幕处理核心继续固定为
[FineSub v0.5.1](https://github.com/caca2331/finesub/tree/v0.5.1)。

## 本版更新

### 更新过程不再留下残缺版本

- 完整更新期间会写入进度标记，用户误点旧快捷方式时只显示“正在完成更新”，不会与更新器
  同时修改安装目录；
- 启动时会核验当前应用快照，发现残缺后自动切回最近的完整版本；没有任何可用版本时显示
  “安装损坏，请重新安装”，不再弹出 PyInstaller 异常窗口；
- 修复完整更新复制失败时的回滚顺序，先移除新载荷，再恢复备份，避免旧文件被误删；
- 更新器重新启动主程序时会明确传递接管状态，降低更新完成前重复启动造成的竞争。

### 本地 Agent 检测与任务选择可真正联动

- 每次手动检测都会刷新 Windows 用户和系统 PATH，并识别原生可执行文件、npm 安装、
  WorkBuddy 自带运行时、Codex 桌面安装以及磁盘根目录下的 `deepseek-harness` 源码；
- 检测可选 CLI 时抑制 Windows 子进程错误对话框，错误会回到检测列表中显示，不再由
  `node.exe` 弹窗打断；
- 检测出的具体命令会传给单任务、批处理和知识库工作进程，不再出现“检测到了但任务用不到”；
- “新建任务 → 纠错翻译”新增按任务的模型选择，可区分 API 模型、本地 Agent 和智能模型组，
  并直接标出当前是否可用；路由不匹配时停留在任务页并给出针对性提示。

### API 密钥保存、引导与路由状态一致

- Gemini 前两个输入项改为“API 密钥（免费额度池）”和“API 密钥（付费额度池）”；
- Gemini、Exa、Tavily 均提供本地化的中英文获取教程和官方入口，只有用户主动点击后才会
  打开浏览器；原生桥接只允许预先审核的官方链接；
- 保存或删除密钥后会立即刷新模型可用状态，避免“已经填写 API 仍显示不可用”；
- 当凭据已保存但模型、执行策略或媒体能力不匹配时，提示会明确要求在当前任务中改选可用
  路由，不再误导用户重复填写密钥。

## 安装与更新

- RC5 至 RC6：可在“设置 → 应用更新”中检查并安装 RC6.1；
- RC4 或旧版 FineSub Desktop：请手动运行
  `Yanami-Sub-0.1.0-rc.6.post1-Setup.exe` 覆盖安装；
- 新安装：下载安装器及对应 `.sha256` 文件，校验一致后运行。

RC6.1 同时发布完整安装器、便携完整包、应用包、SHA-256 文件以及签名的在线更新清单。
安装包不做付费 Authenticode 证书签名；在线更新清单的项目签名只用于验证下载内容完整性。
