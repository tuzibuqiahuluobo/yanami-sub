# Yanami Sub 0.1.0 RC5.4

RC5.4 是 RC5 系列的 Python 运行环境修复版，版本串为
`0.1.0-rc.5.post4`。字幕处理核心继续固定为
[FineSub v0.5.1](https://github.com/caca2331/finesub/tree/v0.5.1)。

## 本版更新

### 修复：检查本机 Python 时界面像卡住

旧版会在应用启动、资源状态刷新和点击安装时同步扫描 Python；每个候选最多等待 15 秒，
多个失效路径会把等待时间继续叠加。用户既看不到进度，也无法决定是否跳过扫描，容易误以为
下载器卡死。

RC5.4 将普通状态读取改为无探测的快速检查，并把真正的解释器扫描放进明确的 Python
准备流程：

- 打开准备弹窗后立即显示检查状态，不阻塞资源页面；
- 单个候选最多等待 3 秒，整轮自动发现最长约 12 秒；
- 找到 Python 3.12 时显示具体版本和路径，可直接使用；
- 没找到时列出已检查路径及拒绝原因，并明确提供“指定解释器”和“下载私有 Python”；
- 手动选择 `python.exe` 后立即生效，不再要求重启应用；
- 重新打开检查或运行诊断会刷新结果，能识别应用启动后新安装的 Python。

因此，本机已有合适 Python 的用户不会再先走 2.8 GB 的私有 Python 下载；版本不匹配、
路径失效或无法运行时也会得到可操作的原因，而不是停在“正在检索”。

### 修复：Windows 上安装私有 Python 报 `os error 448`

当本机没有可复用的 Python 3.12 时，Yanami Sub 仍可通过 `uv` 准备隔离的私有 Python。
部分启用 OneDrive Files On-Demand 的 Windows 环境会在 `uv python install` 创建次版本链接时
报“不受信任的装入点”（`os error 448`）。RC5.4 除原有的 Python 安装目录外，也把
`UV_DATA_DIR` 固定到安装目录下的本地运行时数据目录，避开会触发该问题的漫游/同步路径。

### 保持任务环境隔离

复用系统 Python 只用它作为创建受管虚拟环境的基础解释器；Yanami Sub 的 AI 依赖仍按锁文件
安装到自己的运行环境，不会向用户的系统 Python 逐个写包，也不会依赖系统环境里恰好安装的
第三方模块。

### 新增：启动更新公告与历史版本记录

自动检查发现新版本后，会显示与当前主题一致的更新公告，先给出本版完整说明并询问是否在
应用内下载。公告可以暂时关闭；选择“不再自动显示”会同步关闭“设置 → 应用更新”里的
自动检查开关，之后仍可随时手动检查并重新开启。

应用内更新保持为推荐入口，会继续校验签名清单与下载文件。GitHub 发行页作为完整覆盖安装的
备用入口显示，不与主操作争抢层级。公告还内置 RC3 至 RC5.3 的更新历史，默认不加载、不展开，
只有用户点击“加载历史更新”后才显示。

## 安装与更新

- RC5、RC5.1、RC5.2、RC5.3：可在“设置 → 应用更新”中检查并安装 RC5.4；
- RC4 或旧版 FineSub Desktop：请手动运行
  `Yanami-Sub-0.1.0-rc.5.post4-Setup.exe` 覆盖安装；
- 新安装：下载安装器及对应 `.sha256` 文件，校验一致后运行。

本版修改了随完整程序冻结的启动器与桥接层，所以在线更新统一下发 **full 完整包**，不会把
新前端与旧启动器拼成不兼容的增量安装。安装包不做付费 Authenticode 证书签名；发布资产
提供 SHA-256 校验，在线更新清单继续使用项目发布密钥签名，用于验证下载内容完整性。
